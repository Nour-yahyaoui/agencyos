# Code review — 2026-11-08

Scope: a source review of the NestJS API (`apps/api`, mirrored into `apps/api-serverless`), the serverless adapter and the Next.js client. It builds on the [2026-11-07 audit](audit-2026-11-07.md) and does not repeat its findings. Logging style (`console.*`) was out of scope.

Verification: API and serverless typecheck, API/web lint (0 errors), API build, Next.js production build, and 42 unit tests (19 new tests in `src/common/review-regressions.spec.ts`). The Prisma engines could not be downloaded in the review sandbox, so **the database-backed integration and e2e suites were not run here**. CI runs them against PostgreSQL; check that they pass before merging.

## Fixed in this PR

### Security

| # | Issue | Fix |
|---|---|---|
| S1 | **A password change kept every other session alive.** `PATCH /users/me` changed the hash but left all refresh sessions (for example a stolen device) valid for up to 7 days, and left any outstanding reset links usable. | Revokes all other refresh sessions and unused reset tokens in the same transaction. The current session is kept. |
| S2 | **Login throttling collapsed into one global bucket behind a proxy.** The browser reaches the API through the Next.js `/api` rewrite, but `main.ts` never set `trust proxy`. Every request therefore had the proxy's IP, so 10 failed logins per minute from anyone locked **everyone** out of login, registration and password recovery. | New optional `TRUST_PROXY` setting (hop count, `loopback` or CIDR list), enabled in `docker-compose.yml`. `x-powered-by` is disabled too. |
| S3 | `PATCH /milestones/:id` had **no runtime validation**: its body type `Partial<MilestoneDto> & {…}` is erased, so `ValidationPipe` saw `Object`. Values of any type or length reached Prisma, and an invalid date returned a 500. | Added a real `UpdateMilestoneDto`. Delete is now project-scoped and audited. |
| S4 | Client `website` accepted `javascript:1` and scheme-less hosts, and the client page rendered it as `href`. | The DTO requires http(s). The UI also passes it through `safeExternalUrl()` and uses `rel="noopener noreferrer"`. |
| S5 | A super-admin could deactivate or demote their own account (possibly the platform's last admin). Deactivating a user did not revoke refresh sessions. | Self-lockout is blocked, and deactivation revokes sessions. |
| S6 | Promoting a `CLIENT` member to an agency role skipped the **seat limit** and kept the `clientId` link. Invitations stored a `clientId` on agency roles. | Seats are checked on promotion. `clientId` is cleared or ignored for non-client roles. |
| S7 | Removing a member left their `ProjectMember` rows and task/ticket assignments behind. If re-invited, they silently regained the same project access. | Removed in one transaction with the membership. |
| S8 | The client-supplied `x-request-id` was echoed in logs and response headers without limits. | Only `[A-Za-z0-9._:-]{1,128}` is accepted. Anything else gets a generated id. |
| S9 | The Vercel cron secret was compared with `!==`. | Constant-time comparison. |
| S10 | Onboarding steps, contacts, invoice items and other arrays or strings were unbounded or untyped. | Nested DTOs and size limits. Multipart `projectId`/`clientId` must be strings. |

### Bugs

| # | Issue | Fix |
|---|---|---|
| B1 | **Stripe amounts were always multiplied by 100.** A ¥1,000 (JPY) invoice was charged ¥100,000, and three-decimal currencies (KWD, TND…) were also wrong. The currency was only checked for being 3 characters long. | `toMinorUnits()`/`fromMinorUnits()` follow Stripe's zero- and three-decimal currency lists. The webhook compares exact minor units **and the currency**, and `currency` must match `^[A-Za-z]{3}$`. |
| B2 | The failed-payment webhook ran `payment.create().catch(() => undefined)` **inside an interactive transaction**. In PostgreSQL a failed statement aborts the whole transaction, including the webhook dedupe row. | Upsert on the unique `providerPaymentId`. |
| B3 | **The status filters on Clients and Support always returned 400.** They used `@Query() PaginationDto` plus `@Query('status')`, and `forbidNonWhitelisted` rejects `status` (the bug `TaskQueryDto` already documents). Invalid values would also have caused a Prisma 500. | `ClientQueryDto` / `TicketQueryDto` with enum validation. |
| B4 | **Project activity was usually incomplete.** It loaded the organization's latest 100 audit events and filtered them in memory, so a project's history vanished once other projects produced 100 newer events. | Queries the audit log for the project directly, in the same way as the client activity feed. |
| B5 | `PATCH /tasks/:id` with `status: DONE` **bypassed the prerequisite rule** that the Kanban move enforces. | Shared `assertNoOpenPrerequisites()`. |
| B6 | Moving a task to another project kept the old project's milestone and dependencies, and did not check that the assignee belongs to the new project. | The milestone is reset, references are re-validated and cross-project dependencies are dropped, atomically with the update. |
| B7 | Concurrent invoice creation computed the same `count + 1` number, and the second request failed with a 409. | Retries the next number on a unique collision. |
| B8 | The analytics revenue months were built from local midnight and keyed with `toISOString()`. On any server with a positive UTC offset (for example UTC+1), every bucket shifted by one month. | Buckets are computed in UTC. |
| B9 | Every ticket PATCH (reassignment, priority) notified **and e-mailed** all client users. | Clients are only notified when the status changes. |
| B10 | The web API client called `JSON.parse` on every response, so a proxy's HTML 502/504 page threw a `SyntaxError` instead of an `ApiError`. | Parse errors are handled. |
| B11 | Unmapped Prisma errors were turned into 400 responses and never logged. | They are now logged, with the Prisma code. |

### Heavy queries

| # | Before | After |
|---|---|---|
| H1 | `GET /projects` loaded **every task row** of every listed project (up to 100) to compute progress. | Two `groupBy` queries (`ProjectsService.taskStats`). |
| H2 | The analytics dashboard loaded **every invoice in the organization**, every task of 56 projects, and every open task of every member on each view. | `aggregate`/`count` for invoices, `groupBy` for project and workload stats. |
| H3 | The reminder job scanned **every overdue task ever** across all organizations (`dueDate <= now+48h` has no lower bound), on every run, with one dedupe `count` per task followed by sequential sends. | A 14-day lookback window, one batched dedupe lookup, a 2,000-row cap and concurrency of 10. |
| H4 | The dependency cycle check ran one query per visited task. | Loads the project's dependency graph once. |
| H5 | `notify()` without a dedupe key performed an upsert on a random key. | Plain `create`. |

## Not changed (needs an owner's decision)

These are product or architecture decisions, or need infrastructure. They are listed by priority.

1. **No email verification.** Anyone can register with any address. The invite endpoint also returns the raw invitation URL to the inviter, so a manager can accept an invitation for an address that has no account yet and choose its password. Consider verified email before an account becomes usable.
2. **`NODE_ENV` defaults to `development`.** If production ever runs without `NODE_ENV=production`, password-reset links are returned in API responses and any `*.e2b.app` origin passes the CSRF origin check. Consider failing closed (no default) or an explicit `ALLOW_DEV_RESET_LINKS` flag.
3. **The developer role sees all finance data**: every invoice including drafts, Stripe checkout for any invoice, and organization revenue in analytics. It also sees every client, including internal notes. Confirm this is intended.
4. **Clients can read internal task comments** on their projects. Consider internal and client-visible comments.
5. **Amounts in different currencies are summed together** in "outstanding" and "revenue" (USD + EUR + JPY). Group them by currency.
6. **Editing a sent invoice** does not expire its open Stripe Checkout session. The webhook now rejects the mismatch, but the customer is still charged. Expire `stripeSessionId` on update or void, and consider blocking edits while a checkout is open. Two concurrent checkouts can also both be paid.
7. **Activity feeds filter on `metadata->>'projectId'` / `'clientId'`.** JSON path filters cannot use the existing indexes. Add explicit `projectId`/`clientId` columns, or an expression index, to `AuditEvent`.
8. **No retention jobs.** `RefreshSession`, `PasswordResetToken`, `Notification`, `WebhookEvent` and `AuditEvent` grow forever. Add a cleanup task to the existing cron.
9. **Access tokens cannot be revoked** before they expire (15 minutes) after logout, a password change or deactivation. This is already noted in the previous audit; a `sessionVersion` claim would fix it.
10. **The serverless API is a committed copy of `apps/api/src`.** Every change has to be synced and reviewed twice. Consider a shared package or a build-time copy.
11. **Swagger UI is public in production**, and the serverless version loads unpinned `swagger-ui-dist@5` from unpkg with no SRI. Gate it or self-host it.
12. **The Vercel deployment's client IP.** The serverless adapter trusts one proxy hop. Verify which address the API project sees when it is reached through the web project's rewrite. If it is the web edge, per-IP throttles there share one bucket too (see S2).
13. **The organization detail endpoint** (`GET /organizations/:orgId`) shows subscription and invoice counts to `CLIENT` members.
14. **Downloads load the whole file into memory.** `signedDownload()` exists but is unused. With S3 configured, redirect to a short-lived signed URL.
